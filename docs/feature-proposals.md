# Feature Proposals for reli-prof

## 1. Differential Profiling (差分プロファイリング)

2つのトレース結果を比較して、パフォーマンスの変化を可視化する機能。

**ユースケース:**
- デプロイ前後のパフォーマンス比較
- コード変更による影響の定量評価
- CI/CDパイプラインでのパフォーマンスリグレッション検出

**実装案:**
- `converter:diff` コマンドの追加
- 2つのトレースファイルを入力として受け取り、関数ごとの出現頻度の差分を出力
- differential flamegraph (赤/青の差分フレームグラフ) のSVG生成対応
- 閾値を超えるリグレッションがあった場合に非ゼロ終了コードを返すオプション (CI連携用)

---

## 2. コンテナ内プロセスのプロファイリング

Docker/Podmanコンテナ内で動作するPHPプロセスのプロファイリングをより簡単にする機能。

**ユースケース:**
- 本番に近い環境 (コンテナ) でのプロファイリング
- Kubernetes Pod内のPHPプロセス分析

**実装案:**
- `--container <container-id>` オプションの追加
- `nsenter` を利用したnamespace越えのメモリ読み取り
- `/proc/<pid>/root` 経由でのコンテナ内ファイルシステムアクセス (ELFバイナリの解決)
- コンテナランタイム (docker/podman) からのPID解決ヘルパー

---

## 3. 自動ボトルネック検出・レポート生成

トレース結果を分析し、パフォーマンスボトルネックを自動的に特定してレポートを生成する機能。

**ユースケース:**
- プロファイリングに詳しくない開発者でもボトルネックを特定できる
- 定期的なパフォーマンス監視の自動化

**実装案:**
- `inspector:analyze` コマンドの追加
- ヒューリスティクスに基づく検出:
  - CPU集中関数 (サンプルの一定割合以上を占める関数)
  - 深い再帰呼び出しの検出
  - N+1クエリパターンの検出 (同一関数の高頻度呼び出し)
- テキスト/JSON/HTML形式でのレポート出力
- 重要度によるランク付け

---

## 4. pprof形式のサポート

Google pprof形式への変換を追加し、Go/Rustエコシステムのツールチェーンとの互換性を実現。

**ユースケース:**
- `go tool pprof` による対話的な分析
- pprof Web UIでの可視化
- 他言語のプロファイルとの統一的な閲覧

**実装案:**
- `converter:pprof` コマンドの追加
- Protocol Buffers形式 (profile.proto) での出力
- サンプル値としてwall-time/sample-countを含む
- `--http` オプションでpprof互換のHTTPエンドポイントを提供

---

## 5. メモリリークの時系列検出

メモリ使用量を時系列で追跡し、リーク傾向を自動検出する機能。

**ユースケース:**
- 長時間稼働するデーモンプロセスのメモリリーク発見
- メモリ増加の原因となるオブジェクト/配列の特定

**実装案:**
- `inspector:memory` に `--watch` / `--interval` オプションを追加
- 定期的なメモリスナップショット取得
- オブジェクトクラス別・サイズ別のメモリ増加トレンド分析
- 増加率が閾値を超えた場合のアラート出力
- JSON Lines形式での時系列データ出力 (外部ツールでのグラフ化用)

---

## 6. トレースフィルタリング・集約機能

トレース収集時および変換時にフィルタリングと集約を行う機能。

**ユースケース:**
- 特定のnamespace/関数だけを対象にした分析
- フレームワーク内部コードの除外
- リクエスト単位でのグルーピング

**実装案:**
- `--include-pattern` / `--exclude-pattern` オプション (正規表現)
- `--collapse-pattern` で特定のフレームを折りたたむ (例: フレームワーク内部を1つにまとめる)
- `--group-by` オプション (リクエストURL、エントリポイント等でグループ化)
- フィルタはトレース収集時 (`inspector:trace`) と変換時 (`converter:*`) の両方で利用可能

---

## 7. PHP 8.5対応

次期PHP 8.5リリースへの対応準備。

**実装案:**
- `src/Lib/PhpInternals/Headers/v85.h` の追加
- ZendEngine内部構造体の変更への追従
- PHP 8.5のOpcodeマッピング追加
- CIでのPHP 8.5 RC版でのテスト

---

## 8. Webベースのプロファイルビューア

プロファイル結果をブラウザで対話的に閲覧できるビルトインWebサーバー機能。

**ユースケース:**
- speedscope等の外部ツールなしで結果を可視化
- チームメンバーへの結果共有

**実装案:**
- `inspector:serve` コマンドの追加
- ReactPHP/Amphp HTTPサーバーによる軽量Web UI
- flamegraph/callgraphのインタラクティブ表示
- 複数のプロファイル結果の一覧・比較機能
- WebSocket経由でのリアルタイムトレース表示 (`inspector:top` のWeb版)

---

## 優先度の提案

| 優先度 | 機能 | 理由 |
|--------|------|------|
| 高 | 6. トレースフィルタリング | 既存機能の改善で実装コスト低、ユーザビリティ向上大 |
| 高 | 1. 差分プロファイリング | CI/CD連携の需要が高く、独自の価値を提供 |
| 中 | 5. メモリリーク時系列検出 | 既存のメモリプロファイラの自然な拡張 |
| 中 | 3. 自動ボトルネック検出 | 初心者ユーザーへのアクセシビリティ向上 |
| 中 | 4. pprof形式サポート | エコシステム連携強化 |
| 低 | 2. コンテナ対応 | 技術的に複雑だが需要は大きい |
| 低 | 7. PHP 8.5対応 | リリーススケジュールに依存 |
| 低 | 8. Webビューア | 実装コスト大、既存ツール (speedscope) で代替可能 |
